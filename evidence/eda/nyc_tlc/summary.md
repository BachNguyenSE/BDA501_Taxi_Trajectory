## What the data CAN show
Busiest OD pair: Upper East Side South (Manhattan) → Upper East Side North (Manhattan) (150,440 clean trips) — see `top_od_speed_by_hour.png`.
Median speed ranges from 7.1 mph at 10:00 (hours with ≥1,000 trips) to 13.6 mph at 5:00, so congestion is visible in aggregate, but the data cannot say **where** along the way the slowdown happens.

## Requirement feasibility
| requirement | feasible | evidence |
|---|---|---|
| Trip duration / ETA prediction | YES | pickup/dropoff timestamps + PU/DO zone IDs give a clean regression label |
| Locate congested AREAS along the way | NO | no coordinate columns (0 lat/lon/polyline columns); only 2 zone IDs per trip, so slowness cannot be attributed to any intermediate area |
| Suggest a ROUTE (sequence of areas) | NO | no intermediate positions → no zone-to-zone transition graph can be learned |
| Speed per area per hour | PARTIAL | only an average speed per OD pair (e.g. Upper East Side South (Manhattan) → Upper East Side North (Manhattan)); 4.8% of trips start and end in the same zone |

**Conclusion:** NYC TLC supports zone-level ETA regression only. The project's congestion-area and
route-suggestion goals require intermediate GPS positions, so the dataset was replaced by a GPS
trajectory dataset (see `evidence/eda/porto/summary.md`).
